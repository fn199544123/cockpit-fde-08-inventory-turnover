## 智能仓储库存周转看板解决什么问题？

面向仓储物流，围绕“出入库、库存周转与补货预警”提供可操作的演示系统。当前交付状态：**已完成中台功能验收；用于业务演示，未完成生产部署验收**。

## 系统架构

```text
浏览器页面 → JavaScript 校验与业务计算 → localStorage
浏览器页面 ← 列表 / 指标 / CSV ← 当前浏览器中的演示记录
```

cockpit 用于 AI 开发过程，不是此系统运行的必需服务。本系统没有因为使用 AI 开发而自动接入运行时大模型。

## 本地运行

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 http://127.0.0.1:8000/index.html 。无需构建或后端依赖，也可直接打开 index.html；建议固定 HTTP 地址，避免浏览器存储来源变化。

## 操作与业务规则

## 操作路径

1. 点击“新增批次”，填写 `DEMO-` 开头的虚构唯一编号、品名、车间、库位、入库日期、到期日期及整箱数量。保存同时生成初始入库流水。
2. 在台账点击“入库”，补充同一批次；不同生产批次应新增登记。过期批次禁止补充入库。
3. 在 FIFO 工作台选择品名、出库车间范围，检查推荐顺序，输入数量后点击“按 FIFO 确认出库”。系统跨批次扣减并生成每批出库流水。此工作台的范围独立于台账筛选，页面有明确说明。
4. 搜索编号或品名，组合选择车间、品名与临期/过期/呆滞状态。指标、风险分布、台账、流水和两个 CSV 导出同步使用当前筛选批次。
5. 点击“编辑”，可修改车间、库位、日期及结存。必须提供原因；数量差额作为今天的库存调整留痕。编号和品名锁定以保持流水关联。入库日期不能晚于任何后续流水，到期日期不能早于历史出库日期。
6. 展开“预警参数与周转率口径”，修改临期天数、呆滞天数、统计期间并应用。
7. “重置演示”须二次确认；取消保留数据，确认仅重置本应用的存储键。

## 可复核业务口径

- 单位统一为整箱，库存范围 0～1,000,000；出入库操作必须为正整数，禁止负数、零、非整数和超量出库。
- FIFO：有库存且到期日期不早于今天的批次，按入库日期升序，同日按编号排序。出库不足时整单拒绝，不产生部分扣减。
- 日期按浏览器本地日历日计算；到期当天仍可出库，剩余天数为 0。入库不得填未来日期，到期不得早于入库。
- 临期：库存大于 0 且剩余天数为 0～临期阈值。过期不计入临期。
- 呆滞：有库存，且距离最近出库日期（没有出库则入库日期）达到阈值。补货、盘点修正不刷新最近出库日期。呆滞与过期/临期可以重叠。
- 数量周转率 = 最近 N 天实际出库箱数 ÷ N 天每日结存箱数算术平均值。每日结存由初始入库、补充入库、出库、库存调整流水重建；登记前为 0，含今天和过期库存。不是财务成本周转率，出库调整不混算。平均库存为 0 显示“— / 无有效基数”，有库存无出库显示 0.00。
- 当前筛选确定批次集合，流水区显示其全部历史，不被周转统计期间截断。修改历史登记日期会重算相关期间日均库存，并记录日期变更原因。
- “实时”表示操作后立即重算，打开页面期间每分钟检查是否跨日。“智能”表示以上可解释规则，不是 AI 算法。

## 数据与边界

页面明确标识“演示数据·仅当前浏览器保存”，使用 `development-8-inventory-v1` localStorage 键。建议使用单一标签页；不提供跨标签页并发写入协调、多账号、多人后端、真实冷库硬件、通知服务、扫码设备或外部接口。浏览器清理数据、隐私模式或更换源地址可能丢失本地记录，CSV 可用于人工留档，暂不提供 CSV 回导。

存储写入失败时操作不会提交，页面显示错误。初始样例日期以首次打开/重置当天为基准生成，此后刷新不会自动重建。企业字段固定为某企业，请勿输入真实客户信息。过期库存可以通过有原因的库存调整处理，但没有专门的报废审批流程。
